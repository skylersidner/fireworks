# Phase 2 acceptance: the prototype is the oracle for golden values, and parity deviations are listed explicitly

> **Superseded in part by .squad/decisions/README.md §5 and luigi-2c-dirty-flag-and-notice-hold.md on 2026-11-13:** the draft bullet below (no `persistence`, `starBudget`, `mode` or `activeBreak`, and sky only) is replaced: the draft keeps shell, display settings and active tab. Q1 (fps bar), Q2, Q3 and Q4 are answered (fps benched; designer usable with API down; `/status`; draft scope as above). The golden-oracle, deviation-list and Apply-normalize points stand. The current criteria are in `docs/fireworks-app/acceptance/phase-2.md`.

**What**
- `docs/fireworks-app/acceptance/phase-2.md` sets what "done" means for Phase 2. It has criteria 2a.1–2d.7 and parity rows P1–P27.
- Golden playback values (2a.7) are generated by running the prototype's own simulation code headless. The recording script is checked in.
- Intended deviations from the prototype are marked **(deviation)** in the parity table, and a row passes only on the deviation:
  - The HUD updates about 4 times a second.
  - The JSON panel includes `sky`.
  - Apply runs `normalize`, which clamps values, fills defaults and rejects unknown enum values.
  - Apply rejects more than 4 breaks.
- The draft (`fireworks.draft.v1`) is the §3.3 ShellDocument with `sky`. It never holds `persistence`, `starBudget`, `mode` or `activeBreak`, and a corrupt draft falls back to Peony silently. This default is pending Skyler's answer to Q4.

**Why**
- A golden value recorded from the port only freezes the port. Parity needs an independent oracle (`toad-oracle-and-real-host-shapes.md`).
- If deviations aren't written down, a reviewer can't tell an intended difference from a regression.

- The fps bar (Q1), API-down behavior (Q2), the status route (Q3) and the draft's scope (Q4) stay open until Skyler answers. The defaults in the doc are recommendations.
- The 2c reduced-motion and photosensitivity scope belongs to Rosalina's design-review (criterion 2c.14).
