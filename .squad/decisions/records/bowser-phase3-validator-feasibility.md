# Phase 3: C# validator feasibility (Phase 4 builds it)

**Author:** Bowser · **Date:** 2026-11-13 · **Status:** proposed (for Skyler to promote, or not)
**Reviewed:** `docs/fireworks-app/schema.md` (§2, §5, §6, §9, §12.4), `.squad/decisions/records/yoshi-phase3-creation-schema.md`, `src/web/fireworks-web/src/engine/model/{normalize,limits,shell}.ts` (limits.ts already has `MIN_SHOW_CUES = 1` for the "empty show is invalid" ruling), `src/api/Fireworks.Api/{Program.cs,Services/ServiceResults.cs}`.
**Evidence:** scratch probes on .NET 11.0.0 (SDK 11.0.100), Kestrel, and the compose Postgres 18.6. Nothing in `src/` changed. The probe projects lived in the session scratchpad (`probes/JsonProbe`, `probes/WalkerProbe`, `probes/WebProbe`) and are not kept; the load-bearing results are copied below.

## What

1. **The `JsonElement` walker is feasible and emits the doc's paths and codes exactly, reporting every issue.** A probe `CreationDocumentValidator` (shell and show) matched the expected multiset on 55 cases taken from schema.md §12 (structure, version, enums, numbers, names, embedded shells, cues, kind-mismatch, server-only duplicate keys). Negative controls: replacing `\z` with `$` failed 2 cases, dropping the `IsFinite` check failed 1, and dropping the `ValueEquals` try/catch crashed the walk with `InvalidOperationException` (a 500 in production).
2. **Numbers: read with `TryGetDouble`, then check `double.IsFinite` yourself.** On .NET 11 `TryGetDouble` returns **true** for `1e400` with `+Infinity` (schema.md §6.5 says it returns false; it does not). Integer by value: `d == Math.Floor(d)` (`120.0`, `1e2`, `1293847.0` pass; `TryGetInt32` rejects all three). Range on the raw double first: `0.8500000000000001 > 0.85` is true, so it is `out-of-range`. `1e-400` reads as `0`, the same as `JSON.parse`. No rounding anywhere on the server.
3. **Duplicate keys: parse with the default options (duplicates kept) and detect them in the walker.** `JsonDocumentOptions.AllowDuplicateProperties = false` exists and throws, but its `JsonException` has **no path** (`Path`, `LineNumber` and `BytePositionInLine` all null for `JsonDocument`; the serializer gives only `$`), so it cannot produce `breaks[0].stars`. With defaults, `EnumerateObject()` yields both properties (escape-equal names like `"stars"` compare equal after unescaping). The walker reports `duplicate-key` once per repeated name and walks the **last** value, which is what `JSON.parse` gives the TS walker, so the rest of the multiset stays identical. Postgres `jsonb` would silently keep the last value too (measured), so this check is the only place a duplicate is ever seen.
4. **Unpaired surrogates: `JsonDocument.Parse` does not throw; `GetString()` throws `InvalidOperationException`** ("Cannot read incomplete UTF-16 JSON text as string with missing low surrogate." for `\ud800`; "Invalid surrogate value: '0xDC00'." for `\udc00`). `ValueEquals` returns false for `"Pe\ud800ony"` but **throws** for `"\udc00\ud800"`, and `JsonProperty.Name` throws on a property name with a lone surrogate. Raw invalid UTF-8 (`0xFF`, CESU `ED A0 80`) also parses and only throws at `GetString`. So:
   - Gate the whole body with `System.Text.Unicode.Utf8.IsValid` before parsing; invalid UTF-8 is `("", not-json)`.
   - Wrap every `ValueEquals` in try/catch (a throw means "no match", so `enum`).
   - For `name`, catch the `GetString` failure and unescape the raw token (`GetRawText()`) in a small fallback that keeps lone surrogates, then run the normal §6.4 pipeline. `"Pe\ud800ony"` is then `name-format`, `"\ud800"` is `missing`, as the doc says.
5. **Names: `Trim(char[])` with the JS set, and runes, work as specified.** Measured: `Trim()` misses U+FEFF and strips U+0085; `Trim(jsWs)` does the opposite. U+0085 is Cc, so cleaning removes it either way. 80 emoji: `Length` 160, `EnumerateRunes().Count()` 80. `EnumerateRunes` counts a lone surrogate as one U+FFFD rune, so count only after cleaning. Cc test: `char.GetUnicodeCategory(c) == UnicodeCategory.Control`.
6. **`\u0000` never reaches Postgres.** Postgres 18.6 rejects `\u0000` in `jsonb` ("unsupported Unicode escape sequence") and also rejects lone surrogate escapes ("Unicode low surrogate must follow a high surrogate"). The walker rejects a NUL name as `name-format`, and nothing else stored is free text: enums, keys and ids are matched against fixed sets or the ASCII key pattern, and unknown properties are rejected, not stored. The stored text is re-serialized from the validated DTO, never the request bytes. STJ's escaped output (`🎆`, `<`) is accepted by `jsonb` (measured).
7. **256 KiB with `[RequestSizeLimit(262144)]` and 413 works**, under this app's `AddProblemDetails()` + `UseExceptionHandler()`: 413 (ProblemDetails body) for both an oversize `Content-Length` and a chunked body; 262,143 bytes is accepted. A 1000-cue, 32×4-shell show is 78.9 KB and parses and validates in about 5 to 8 ms.
8. **Read the body in the action; don't bind `[FromBody] JsonElement`.** Measured: with binding, unparseable JSON comes back as MVC's ModelState ProblemDetails (not our `{ message, errors }` shape), an empty body gives "A non-empty request body is required.", and **invalid UTF-8 binds successfully** and would throw later in the walker. Reading `Request.Body` into a buffer still gets the 413 from `[RequestSizeLimit]`, and gives us `Utf8.IsValid`, our `not-json`, and paths. Add `[Consumes("application/json")]`: the manual action accepted `text/plain` in the probe. The request records (`CreateCreationRequest(string Kind, JsonElement Document)`, `UpdateCreationRequest(JsonElement Document)`, `RemixCreationRequest(JsonElement Document)`) are built by a small envelope walk, so they still state exactly what the API accepts.
9. **Anchor .NET regexes with `\z`, not `$`.** In .NET, `$` also matches before a final `\n`. Measured: key pattern `^[A-Za-z][A-Za-z0-9_-]{0,11}$` accepts `"s2\n"` as a shell key and `"c1\n"` as a cue id; the share-code route constraint with `$` matched `abcdefgh%0A` (route value `"abcdefgh\n"`, length 9) and reached the action, so "no database query for a bad code" fails. With `\z`, all three are rejected (key-format; route 404). JS `$` without the `m` flag doesn't have this, so the TS side is fine. Also avoid `RegexOptions.IgnoreCase` on these (it lets `[A-Za-z]` match the Kelvin sign U+212A).
10. **Item 8 of the brief: no objection** to write-time `name`, `schema_version` and `palette` columns, or to remix taking `{ document }`. `palette` as an EF primitive collection (`List<string>`: `text[]` on Npgsql, JSON text on SQLite) is fine because it is never queried. `name varchar(80)`: Postgres counts characters, not bytes or UTF-16 units (`'🎆🎆🎆'::varchar(2)` keeps two emoji), so 80 code points always fit; never check it with `string.Length`. `remixedFrom` is set in the response mapper as `isOwner ? sourceShareCode : null` (Skyler's ruling), always present.

## Proposed C# shape (Phase 4)

- `Services/Creations/CreationLimits.cs`: the §5.1 table (checked against `schema/limits.json` by a test).
- `Services/Creations/CreationDocumentValidator.cs`: `ValidateShell(JsonElement)` and `ValidateShow(JsonElement)` returning `CreationValidationResult<T>(IReadOnlyList<CreationIssue> Errors, T? Document)`, with `CreationIssue(string Path, string Code, string Message)`. Internals: `ReadObject` (unknown-property, duplicate-key, last value wins, ordinal dictionary), `ReadVersion`, `ReadNumber` (missing, type incl. non-finite, out-of-range, not-integer, in that order, one issue per field), `ReadEnum` (safe `ValueEquals`), `ReadName` (§6.4 with the raw-token fallback), `ReadKeyString`. DTOs (`ShellDocumentDto`, `BreakDto`, `SkyDto`, `ShowDocumentDto`, `CueDto`) are built only from a clean walk; integer fields are `int`; `Sky` and cue `BurstHeight` are nullable and omitted with `WhenWritingNull`.
- `Services/Creations/CreationEnvelopeReader.cs`: body bytes → `Utf8.IsValid` → `JsonDocument.Parse` (default options) → envelope walk (`kind`, `document`) → the request record, or issues at `""`, `kind`, `document`.
- `ServiceError` gains an optional `IReadOnlyList<CreationIssue>? Issues`; `ToErrorResult` writes `{ message, errors }` when present.

## Why

The doc's server approach (§6.5) is right; three of its specific API claims were measured false on .NET 11 (`TryGetDouble` on non-finite, `AllowDuplicateProperties` giving a path, `ValueEquals` never throwing), and two traps it doesn't mention (`$` before `\n`, invalid UTF-8 passing `JsonDocument.Parse` and model binding) would each have produced a wrong accept or a 500.
